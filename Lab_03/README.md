# Лабораторна робота № 3
## Нездатні до змін структури даних (immutability) у Python
**Варіант 15 — Система задач проєкту**

### 1. Предметна область
Програма моделює систему керування задачами проєкту. Кожна задача має ідентифікатор, назву, опис, статус, пріоритет, коментарі, мітки та метадані.

### 2. Реалізація незмінної моделі
- `Task` і `Comment` реалізовані через `@dataclass(frozen=True, slots=True)`.
- Коментарі зберігаються в `tuple`.
- Мітки зберігаються в `frozenset`.
- Метадані представлені `MappingProxyType`; перед створенням proxy дані копіюються.
- Конструктор `Task` додатково нормалізує колекції та створює приватну копію метаданих.

### 3. Pure update-функції
Модуль `core.py` містить функції `add_comment`, `add_label`, `change_status` і `change_priority`. Вони не змінюють передану задачу, а повертають новий об'єкт через `dataclasses.replace`, конкатенацію tuple або операції frozenset.

### 4. Тестування
Тести перевіряють:
- заборону зміни полів frozen dataclass;
- незмінні типи колекцій;
- збереження початкового об'єкта після кожного оновлення;
- read-only поведінку метаданих і копіювання джерела;
- хешованість `Task`;
- валідацію статусу, пріоритету та унікальності коментарів.

### 5. Вимірювання продуктивності
`tests/test_performance.py` порівнює час двох однакових за призначенням сценаріїв: оновлення мутабельної моделі з `baseline.py` та створення нових версій immutable-моделі з `core.py`. Запуск:
```bash
pytest -q --durations=5 -s
```
Результат залежить від обладнання та версії Python. Незмінна модель може мати додаткові витрати на створення копій, але забезпечує передбачуваність стану та спрощує тестування.

### 6. Запуск
Встановити залежності:
```bash
python -m venv .venv
```
Windows:
```bash
.venv\Scripts\activate
```
Linux/macOS:
```bash
source .venv/bin/activate
```
Далі:
```bash
pip install -r requirements.txt
python main.py
```

### 7. Перевірки якості
```bash
pytest -q --durations=5 -s
mypy .
black --check .
ruff check .
```
Для автоматичного форматування:
```bash
black .
```

### 8. Висновок
У роботі реалізовано незмінну модель системи задач проєкту. Застосування `tuple`, `frozenset`, `MappingProxyType` та frozen dataclasses захищає стан задач від випадкових змін. Оновлення виконуються чистими функціями, які повертають нові об'єкти. Тести підтверджують відсутність мутацій, read-only поведінку метаданих і хешованість сутності `Task`. Мікровимірювання дає змогу порівняти витрати часу мутабельного та незмінного підходів.
