# Лабораторна робота №4 — варіант 15
## Задача про рюкзак 0/1

Програма визначає максимальну сумарну цінність предметів, які можна покласти
до рюкзака з обмеженою місткістю. Кожен предмет можна взяти не більше одного разу.
Предмет задається парою `(вага, цінність)`.

### Реалізації
- `knapsack_recursive` — чиста рекурсія без кешування.
- `KnapsackSolver` / `knapsack_memoized` — рекурсія з `@lru_cache`; кешований
  стан має аргументи `(index, remaining_capacity)`.
- `knapsack_iterative` — ітеративне динамічне програмування з одновимірним масивом.
  Перебір місткості виконується у зворотному порядку, щоб не використати предмет двічі.

### Базовий випадок і рекурсивний крок
Базовий випадок: усі предмети розглянуто або вільна місткість дорівнює нулю —
повертається 0.

Рекурсивний крок: для поточного предмета порівнюються два варіанти:
1. не брати предмет;
2. взяти предмет, якщо його вага не перевищує залишкову місткість.
Повертається більша з двох цінностей.

### Мемоізація
`KnapsackSolver._solve(index, remaining)` декорована `@lru_cache(maxsize=None)`.
Методи `cache_info()` і `cache_clear()` дають змогу переглянути статистику кешу
та очистити його. Для одного екземпляра розв'язувача набір предметів і початкова
місткість незмінні, тому ключ кешу відповідає стану `(index, remaining)`.

### Складність
Нехай `n` — кількість предметів, `W` — місткість рюкзака.
Наївна рекурсія має експоненційну часову складність O(2^n).
Мемоізована та ітеративна реалізації мають O(nW) часу.
Мемоізована реалізація зберігає до O(nW) станів; ітеративна використовує O(W)
додаткової пам'яті.

### Обмеження рекурсії Python
CPython має обмеження глибини рекурсії, яке можна переглянути через
`sys.getrecursionlimit()` (типове значення близьке до 1000). Перевищення ліміту
призводить до `RecursionError`. CPython не виконує оптимізацію хвостових викликів
(TCO), тому хвостова рекурсія також використовує стек викликів. Для глибоких
задач безпечніше застосовувати ітеративний алгоритм.
